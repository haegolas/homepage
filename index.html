기타 특기사항 및 주요 구현 기능

기획부터 개발까지 1인 개발로 진행한 액션 플랫포머 게임입니다. 플레이어의 조작감과 타격감을 극대화하기 위해 FSM(Finite State Machine) 패턴을 적용하여 캐릭터 상태를 관리했습니다.

  • FSM(유한 상태 기계) 기반 캐릭터 제어:

    Idle, Run, Jump, Attack 등 복잡한 애니메이션과 상태 전환을 깔끔하게 분리하여 버그를 줄이고 확장성을 높였습니다.

  • 오브젝트 풀링(Object Pooling) 적용:

    투사체(총알, 마법) 및 파티클 이펙트 생성/삭제 시 발생하는 가비지 컬렉터(GC) 스파이크를 방지하여 프레임 드랍을 최적화했습니다.

  • Scriptable Object 활용 데이터 관리:

    몬스터 스탯, 아이템 정보 등을 Scriptable Object로 분리하여 기획자 친화적인 데이터 구조를 설계했습니다.

FSM State Pattern

캐릭터 상태 패턴 구현

거대한 switch-case 문을 피하기 위해 상태 패턴을 적용했습니다. 각 상태를 클래스로 캡슐화하여 새로운 액션(예: 대시, 구르기)을 추가할 때 기존 코드를 수정하지 않고 새로운 클래스만 추가하면 되도록 OCP(개방-폐쇄 원칙)를 준수했습니다.

유지보수성이 크게 향상되었습니다.
PlayerStateMachine.cs
public interface IState
{
    void Enter();
    void Execute();
    void Exit();
}

public class PlayerStateMachine : MonoBehaviour
{
    private IState currentState;

    public void ChangeState(IState newState)
    {
        if (currentState != null)
            currentState.Exit();

        currentState = newState;
        currentState.Enter();
    }

    private void Update()
    {
        if (currentState != null)
            currentState.Execute();
    }
}
